Technical Example: YOLO Object Detection

A simple example showing how an object detector can process an image and return information about detected objects.

Why Use YOLO?

YOLO is useful for obstacle detection because it can identify multiple objects in one image and return their locations using bounding boxes. YOLO-based detectors have been used in several assistive navigation systems reviewed in this tutorial [1] [2] [4].

Basic YOLO Example

The following Python example shows the basic steps for loading a pretrained YOLO model and running object detection on an image. 


from ultralytics import YOLO

# Load a pretrained YOLO model
model = YOLO("yolov8n.pt")

# Run object detection on an image
results = model("street.jpg")

# Examine the detected objects
for result in results:
    for box in result.boxes:

        class_id = int(box.cls[0])
        confidence = float(box.conf[0])
        coordinates = box.xyxy[0]

        print("Class ID:", class_id)
        print("Confidence:", confidence)
        print("Bounding Box:", coordinates)

Step 1: Load the Model

The first line imports the YOLO class from the Ultralytics library. The program then loads a pretrained YOLOv8 Nano model. 


model = YOLO("yolov8n.pt")

The Nano version is one of the smaller YOLO models. Smaller models are useful when speed and computational resources are important, which is especially relevant for mobile applications.

Mobile research demonstrates that model size and input resolution affect both inference speed and detection accuracy [3].

Step 2: Process the Image


results = model("street.jpg")

The image is passed through the neural network. The model analyzes the visual features in the image and predicts objects that it has been trained to recognize.

For a real mobile system, the input would usually come from a camera frame instead of a stored image.

Step 3: Read the Detection Results

Each detected object contains several pieces of information.

  • Class ID: identifies the type of object detected.
  • Confidence: indicates how certain the model is about its prediction.
  • Bounding Box: describes where the object appears in the image. 

class_id = int(box.cls[0])
confidence = float(box.conf[0])
coordinates = box.xyxy[0]

Example Detection

Imagine the model processes a sidewalk image and returns the following: 


Object: Person
Confidence: 0.91
Bounding Box: [210, 85, 410, 620]

This means that the model believes there is a person in the image with approximately 91% confidence. The four bounding-box coordinates describe the location of that person in the image.

Adding a Confidence Threshold

A practical application may ignore detections with very low confidence. For example: 


if confidence >= 0.60:
    print("Possible obstacle detected")

In this example, only detections with a confidence score of at least 0.60 are accepted.

The threshold must be chosen carefully. A very high threshold may cause the system to miss real obstacles, while a very low threshold may produce too many false detections.

From Object Detection to Obstacle Detection

The code above only performs object detection. A complete assistive system would require another decision step.

For example: 


if confidence >= 0.60:

    if object_is_in_user_path:
        warn_user()

The variable object_is_in_user_path represents an additional obstacle-analysis step. A real system could use the bounding-box position, depth estimation, object movement, or the user's direction of travel to make this decision [5] [6].

Simplified Algorithm

The complete process can be represented with the following pseudocode: 


WHILE application is running:

    Capture camera frame

    Resize / preprocess frame

    Run object detector

    FOR each detected object:

        Read class
        Read confidence
        Read bounding box

        IF confidence is high enough:

            Estimate whether object is in user's path

            IF object represents a possible obstacle:

                Generate audio or haptic warning

Why Not Use the Largest YOLO Model?

Larger models may provide better detection performance, but they also require more memory and computation. On a smartphone, that can reduce processing speed and increase battery usage.

This creates an important engineering trade-off:

Higher Accuracy ↔ Faster Processing and Lower Resource Usage

Research on YOLOv8 Android deployment shows this trade-off directly [3].

Alternative Approaches

YOLO is not the only possible approach. Earlier smartphone research has also explored Faster R-CNN [2].

Other approaches use optical flow and feature tracking rather than relying entirely on object classification [5].

For a mobile obstacle detection application, YOLO is attractive because of its ability to balance real-time speed and detection capability. However, combining YOLO with depth or motion information can provide additional information that basic 2D object detection does not provide.

Key Takeaway

The object detector is only one component of an assistive navigation system. YOLO can answer:

"What objects are visible, and where are they?"

The complete obstacle detection system must then answer:

"Which of these objects could interfere with the user's movement?"
